## Complete PostgreSQL Data Types Reference

### Integer Types

| Type | Storage | Range | When to Use |
|------|---------|-------|-------------|
| `SMALLINT` | 2 bytes | -32,768 to 32,767 | Very small counters, age |
| `INTEGER` / `INT` | 4 bytes | -2.1B to 2.1B | Most integer columns |
| `BIGINT` | 8 bytes | -9.2 × 10^18 to 9.2 × 10^18 | IDs on large tables, bytes |

```sql
-- Examples
CREATE TABLE demo_ints (
    tiny_num    SMALLINT,    -- age: 0–150 fits fine
    regular_num INTEGER,     -- order quantities, counts
    huge_num    BIGINT       -- file sizes in bytes, user IDs at scale
);

-- Integer arithmetic
SELECT
    2147483647::INT + 1;    -- ERROR: integer overflow! (max INT is ~2.1B)
    2147483647::BIGINT + 1; -- OK: 2147483648
```

### Serial Types (Auto-Increment — Legacy)

```sql
-- SERIAL is a shorthand — it creates a sequence under the hood
id SERIAL PRIMARY KEY
-- is exactly equivalent to:
id INTEGER DEFAULT nextval('tablename_id_seq') NOT NULL

-- Types:
SMALLSERIAL  -- 1 to 32,767
SERIAL       -- 1 to ~2.1 billion
BIGSERIAL    -- 1 to ~9.2 × 10^18
```

### IDENTITY (Modern Standard — Prefer This)

```sql
-- PostgreSQL 10+ standard way (SQL standard compliant)
id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY
-- or
id INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY

-- GENERATED ALWAYS: cannot insert manual values (unless OVERRIDING SYSTEM VALUE)
-- GENERATED BY DEFAULT: can insert manual values (useful for data migrations)

-- Custom sequence options:
id BIGINT GENERATED ALWAYS AS IDENTITY (START WITH 1000 INCREMENT BY 5) PRIMARY KEY
```

### UUID — Globally Unique IDs

```sql
-- Enable the uuid extension
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
-- or in PostgreSQL 13+
CREATE EXTENSION IF NOT EXISTS pgcrypto;

-- UUID primary key
id UUID DEFAULT gen_random_uuid() PRIMARY KEY   -- PostgreSQL 13+
id UUID DEFAULT uuid_generate_v4() PRIMARY KEY  -- uuid-ossp extension

-- When to use UUID vs SERIAL:
-- UUID: distributed systems, no sequential guessing of IDs, merging databases
-- SERIAL: simpler, smaller storage (4 vs 16 bytes), easier to read in logs
```

### Decimal / Float Types

| Type | Notes | When to Use |
|------|-------|-------------|
| `NUMERIC(precision, scale)` | Exact, no rounding errors | Money, financial calculations |
| `DECIMAL(p, s)` | Same as NUMERIC | Money |
| `REAL` / `FLOAT4` | 4-byte float, ~6 decimal digits | Scientific, imprecise OK |
| `DOUBLE PRECISION` / `FLOAT8` | 8-byte float, ~15 decimal digits | Scientific, imprecise OK |

```sql
-- NUMERIC(10, 2): up to 10 total digits, 2 after decimal
-- Max value: 99999999.99
price   NUMERIC(10, 2)  -- perfect for money
weight  NUMERIC(8, 3)   -- precision matters

-- Floats are IMPRECISE — never use for money
SELECT 0.1::FLOAT + 0.2::FLOAT;  -- 0.30000000000000004 (floating point error!)
SELECT 0.1::NUMERIC + 0.2::NUMERIC;  -- 0.3 (exact)

-- Money type (PostgreSQL-specific — avoid in most cases)
-- It's locale-dependent and causes portability issues
price MONEY  -- stores as $1,234.56 — avoid this
```

### Text Types

| Type | Notes | When to Use |
|------|-------|-------------|
| `TEXT` | Unlimited length | Almost always — PostgreSQL default |
| `VARCHAR(n)` | Max n characters | When you need a hard limit |
| `CHAR(n)` | Fixed n characters, padded | Rare — legacy codes like country codes |
| `"CHAR"` (1 byte) | Single byte | Internal PostgreSQL use only |

```sql
-- PostgreSQL TEXT vs VARCHAR performance: identical
-- TEXT is just VARCHAR without the length limit
-- Use TEXT unless you have a specific reason to limit length

-- VARCHAR(255) is a MySQL habit — not needed in PostgreSQL
-- If you need to enforce length, use a CHECK constraint:
email TEXT CHECK (LENGTH(email) <= 255)

-- CHAR(2) pads with spaces — comparison is tricky
code CHAR(2)  -- 'US' stored as 'US', but 'U' stored as 'U '

-- Practical recommendations:
name        TEXT NOT NULL
email       TEXT NOT NULL
description TEXT
status      TEXT CHECK (status IN ('active', 'inactive', 'pending'))
country_code CHAR(2)  -- ISO 3166-1 alpha-2
```

### Boolean

```sql
-- Only two values: TRUE and FALSE (and NULL)
is_active   BOOLEAN DEFAULT TRUE
is_verified BOOLEAN DEFAULT FALSE
is_deleted  BOOLEAN NOT NULL DEFAULT FALSE

-- PostgreSQL accepts many literals for boolean:
-- TRUE: true, 't', 'yes', 'y', 'on', '1'
-- FALSE: false, 'f', 'no', 'n', 'off', '0'

-- Querying
SELECT * FROM users WHERE is_active = TRUE;
SELECT * FROM users WHERE is_active;        -- same as = TRUE
SELECT * FROM users WHERE NOT is_active;    -- same as = FALSE

-- NULL is neither true nor false:
SELECT TRUE AND NULL;   -- NULL
SELECT FALSE AND NULL;  -- FALSE (short-circuit: FALSE AND anything = FALSE)
SELECT TRUE OR NULL;    -- TRUE  (short-circuit: TRUE OR anything = TRUE)
SELECT FALSE OR NULL;   -- NULL
```

### Date and Time Types

| Type | Storage | Range | Use |
|------|---------|-------|-----|
| `DATE` | 4 bytes | 4713 BC to 5874897 AD | Just the date |
| `TIME` | 8 bytes | 00:00:00 to 24:00:00 | Just the time |
| `TIMESTAMP` | 8 bytes | 4713 BC to 294276 AD | Date + time, no timezone |
| `TIMESTAMPTZ` | 8 bytes | Same | Date + time WITH timezone (preferred) |
| `INTERVAL` | 16 bytes | ±178 million years | Duration between dates |

```sql
-- TIMESTAMPTZ vs TIMESTAMP
-- TIMESTAMPTZ stores in UTC, displays in session timezone
-- TIMESTAMP has no timezone concept at all
-- Always prefer TIMESTAMPTZ for real-world data

created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
updated_at  TIMESTAMPTZ
birth_date  DATE
start_time  TIME
duration    INTERVAL

-- Date literals
SELECT '2024-03-15'::DATE;
SELECT '2024-03-15 14:30:00'::TIMESTAMP;
SELECT '2024-03-15 14:30:00+05:30'::TIMESTAMPTZ;

-- Interval literals
SELECT INTERVAL '2 hours 30 minutes';
SELECT INTERVAL '1 year 3 months 15 days';
SELECT INTERVAL '90 days';

-- Date math
SELECT '2024-03-15'::DATE + 30;              -- 2024-04-14
SELECT '2024-03-15'::DATE + INTERVAL '1 month'; -- 2024-04-15
SELECT NOW() - INTERVAL '7 days';
SELECT AGE('2024-03-15'::DATE, '2020-01-01'::DATE);
-- Output: 4 years 2 mons 14 days
```

### JSON Types

```sql
-- JSON: stores text, validates JSON syntax
-- JSONB: stores binary, indexed, faster queries (ALWAYS prefer JSONB)

metadata JSONB
settings JSONB DEFAULT '{}'

-- Insert
INSERT INTO products (metadata)
VALUES ('{"color": "red", "weight": 1.5, "tags": ["sale", "popular"]}');

-- Query JSON fields
SELECT metadata->>'color' FROM products;           -- returns text
SELECT metadata->'weight' FROM products;           -- returns JSON value
SELECT metadata#>>'{tags,0}' FROM products;        -- first tag as text
SELECT metadata->'tags'->0 FROM products;          -- first tag as JSON

-- Filter on JSON field
SELECT * FROM products WHERE metadata->>'color' = 'red';
SELECT * FROM products WHERE (metadata->>'weight')::FLOAT > 1.0;

-- JSONB containment operator @>
SELECT * FROM products WHERE metadata @> '{"color": "red"}';

-- Check if key exists
SELECT * FROM products WHERE metadata ? 'color';
SELECT * FROM products WHERE metadata ?| ARRAY['color', 'weight'];  -- has any
SELECT * FROM products WHERE metadata ?& ARRAY['color', 'weight'];  -- has all
```

### Arrays

```sql
-- Array types
tags    TEXT[]
scores  INTEGER[]
prices  NUMERIC(10,2)[]

-- Insert arrays
INSERT INTO posts (tags) VALUES (ARRAY['sql', 'database', 'tutorial']);
INSERT INTO posts (tags) VALUES ('{"sql", "database"}');  -- array literal

-- Query arrays
SELECT * FROM posts WHERE 'sql' = ANY(tags);    -- contains 'sql'
SELECT * FROM posts WHERE tags @> ARRAY['sql']; -- contains 'sql' (GIN index)
SELECT * FROM posts WHERE tags && ARRAY['sql', 'python'];  -- overlap

-- Array functions
SELECT ARRAY_LENGTH(tags, 1) FROM posts;    -- length of 1st dimension
SELECT UNNEST(tags) FROM posts;             -- expand array to rows
SELECT ARRAY_AGG(name) FROM products;       -- aggregate rows into array
```

### Other Useful Types

```sql
-- Network addresses
ip_address   INET       -- IPv4 or IPv6 address
mac_address  MACADDR    -- MAC address
network      CIDR       -- IP network (e.g., 192.168.1.0/24)

-- Geometric
point   POINT           -- (x, y)
line    LINE
circle  CIRCLE
polygon POLYGON

-- Range types
valid_dates  DATERANGE    -- range of dates
valid_times  TSTZRANGE    -- range of timestamps
price_range  NUMRANGE     -- range of numbers

-- Currency (avoid money type, use NUMERIC instead)
amount  NUMERIC(15, 4)  -- store in cents or smallest unit

-- Enumerated types
CREATE TYPE order_status AS ENUM ('pending', 'shipped', 'delivered', 'cancelled');
status  order_status DEFAULT 'pending'
-- Pros: storage efficient, clear documentation
-- Cons: ALTER to add values requires table lock; migrations are harder
-- Alternative: TEXT with CHECK constraint (more flexible)
```

## CREATE TABLE — Complete Reference

```sql
CREATE TABLE table_name (
    -- Column definitions
    column_name  data_type  [column_constraint ...],
    ...
    -- Table constraints
    [table_constraint, ...]
);
```

### Column Constraints

```sql
CREATE TABLE users (
    -- Auto-incrementing primary key
    id          BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,

    -- Required text, max 100 chars
    username    TEXT NOT NULL CHECK (LENGTH(username) BETWEEN 3 AND 50),

    -- Unique email, must not be null
    email       TEXT NOT NULL UNIQUE,

    -- Optional text with default
    bio         TEXT,
    country     TEXT DEFAULT 'US',

    -- Positive number
    age         SMALLINT CHECK (age >= 0 AND age <= 150),

    -- Decimal with range check
    balance     NUMERIC(15, 2) NOT NULL DEFAULT 0 CHECK (balance >= 0),

    -- Boolean with default
    is_active   BOOLEAN NOT NULL DEFAULT TRUE,
    is_verified BOOLEAN NOT NULL DEFAULT FALSE,

    -- Timestamps
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at  TIMESTAMPTZ,
    deleted_at  TIMESTAMPTZ,  -- soft delete pattern

    -- Foreign key (column-level)
    team_id     INT REFERENCES teams(id) ON DELETE SET NULL,

    -- Computed/generated column (PostgreSQL 12+)
    -- full_name TEXT GENERATED ALWAYS AS (first_name || ' ' || last_name) STORED
);
```

### Table-Level Constraints (Better for Named Constraints and Composites)

```sql
CREATE TABLE order_items (
    id          BIGINT GENERATED ALWAYS AS IDENTITY,
    order_id    INT NOT NULL,
    product_id  INT NOT NULL,
    quantity    INT NOT NULL,
    unit_price  NUMERIC(10, 2) NOT NULL,

    -- Named constraints — easier to identify in error messages
    CONSTRAINT order_items_pkey PRIMARY KEY (id),
    CONSTRAINT order_items_order_fkey FOREIGN KEY (order_id)
        REFERENCES orders(id) ON DELETE CASCADE,
    CONSTRAINT order_items_product_fkey FOREIGN KEY (product_id)
        REFERENCES products(id) ON DELETE RESTRICT,
    CONSTRAINT quantity_positive CHECK (quantity > 0),
    CONSTRAINT price_positive CHECK (unit_price >= 0),

    -- Composite unique constraint
    CONSTRAINT unique_order_product UNIQUE (order_id, product_id)
);
```

### Foreign Key Actions

```sql
-- ON DELETE / ON UPDATE options:

ON DELETE RESTRICT    -- Prevent deletion if referenced rows exist (default)
ON DELETE CASCADE     -- Delete child rows when parent is deleted
ON DELETE SET NULL    -- Set FK column to NULL when parent is deleted
ON DELETE SET DEFAULT -- Set FK column to default value
ON DELETE NO ACTION   -- Like RESTRICT but checked at end of transaction

-- Example: delete an order → all its items are deleted automatically
order_id INT REFERENCES orders(id) ON DELETE CASCADE

-- Example: delete a customer → set orders.customer_id to NULL
customer_id INT REFERENCES customers(id) ON DELETE SET NULL
```

## ALTER TABLE — Modifying Existing Tables

```sql
-- Add a column
ALTER TABLE customers ADD COLUMN phone TEXT;
ALTER TABLE customers ADD COLUMN loyalty_points INT DEFAULT 0 NOT NULL;

-- Drop a column
ALTER TABLE customers DROP COLUMN phone;
ALTER TABLE customers DROP COLUMN phone CASCADE; -- also drops dependent views/constraints

-- Rename a column
ALTER TABLE customers RENAME COLUMN name TO full_name;

-- Change column type
ALTER TABLE customers ALTER COLUMN loyalty_points TYPE BIGINT;

-- Set or drop NOT NULL
ALTER TABLE customers ALTER COLUMN phone SET NOT NULL;
ALTER TABLE customers ALTER COLUMN phone DROP NOT NULL;

-- Set or drop DEFAULT
ALTER TABLE customers ALTER COLUMN country SET DEFAULT 'US';
ALTER TABLE customers ALTER COLUMN country DROP DEFAULT;

-- Add a constraint
ALTER TABLE customers ADD CONSTRAINT valid_email CHECK (email LIKE '%@%.%');
ALTER TABLE products ADD CONSTRAINT unique_product_name UNIQUE (name);
ALTER TABLE orders ADD FOREIGN KEY (customer_id) REFERENCES customers(id);

-- Drop a constraint
ALTER TABLE customers DROP CONSTRAINT valid_email;
ALTER TABLE customers DROP CONSTRAINT customers_email_key; -- auto-named UNIQUE

-- Rename a table
ALTER TABLE customers RENAME TO clients;

-- Add a column with a sequence
ALTER TABLE old_table ADD COLUMN id BIGINT GENERATED ALWAYS AS IDENTITY;

-- Rename the table
ALTER TABLE customers RENAME TO clients;
```

## NULL — What It Really Means

NULL is one of the most misunderstood concepts in SQL.

**NULL = unknown / missing / not applicable**

It is NOT:
- An empty string `''`
- Zero `0`
- False `FALSE`

```sql
-- NULL comparisons always return NULL (unknown)
SELECT NULL = NULL;     -- NULL (not TRUE!)
SELECT NULL != NULL;    -- NULL
SELECT NULL > 5;        -- NULL
SELECT NULL + 5;        -- NULL
SELECT NULL || 'text';  -- NULL (string concat propagates NULL)

-- NULL in boolean logic (three-valued logic)
SELECT TRUE  AND NULL;  -- NULL
SELECT FALSE AND NULL;  -- FALSE
SELECT TRUE  OR  NULL;  -- TRUE
SELECT FALSE OR  NULL;  -- NULL
SELECT NOT NULL;        -- NULL

-- Checking for NULL
SELECT * FROM employees WHERE manager_id IS NULL;
SELECT * FROM employees WHERE manager_id IS NOT NULL;

-- COALESCE: return first non-NULL value
SELECT COALESCE(phone, email, 'no contact') AS contact FROM customers;
-- If phone is not NULL → return phone
-- Else if email is not NULL → return email
-- Else → return 'no contact'

-- NULLIF: return NULL if two values are equal
SELECT NULLIF(0, 0);     -- NULL (useful to avoid division by zero)
SELECT NULLIF(5, 0);     -- 5
SELECT 100 / NULLIF(quantity, 0) AS safe_division FROM items;

-- NVL (Oracle), IFNULL (MySQL) — PostgreSQL uses COALESCE
SELECT COALESCE(NULL, 'default');  -- 'default'

-- NULL in aggregate functions
SELECT COUNT(*) FROM employees;           -- 10 (counts all rows)
SELECT COUNT(manager_id) FROM employees;  -- 9  (NULL rows are skipped)
SELECT SUM(salary) FROM employees;        -- NULLs are skipped in SUM
SELECT AVG(salary) FROM employees;        -- NULLs excluded from calculation
```

## Schema Best Practices

### Naming Conventions

```sql
-- Tables: plural nouns, snake_case
CREATE TABLE customers (...);
CREATE TABLE order_items (...);

-- Columns: singular nouns, snake_case
customer_id, order_date, unit_price

-- Primary keys: always 'id'
-- Foreign keys: table_name_id (e.g., customer_id, product_id)
-- Booleans: is_active, has_paid, can_edit
-- Timestamps: created_at, updated_at, deleted_at, published_at

-- Constraints: descriptive names
CONSTRAINT orders_customer_id_fkey FOREIGN KEY ...
CONSTRAINT products_price_positive CHECK (price >= 0)
CONSTRAINT users_email_unique UNIQUE (email)
```

### Always Add These Timestamp Columns

```sql
created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
updated_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
-- (Trigger to auto-update updated_at is covered in Lesson 14)
```

### Soft Delete Pattern

```sql
-- Instead of DELETE, set deleted_at
deleted_at TIMESTAMPTZ

-- "Delete" a row
UPDATE customers SET deleted_at = NOW() WHERE id = 5;

-- Query only active rows
SELECT * FROM customers WHERE deleted_at IS NULL;

-- Create a view for convenience
CREATE VIEW active_customers AS
SELECT * FROM customers WHERE deleted_at IS NULL;
```

## Key Takeaways

1. Use `TEXT` over `VARCHAR(255)` in PostgreSQL — they're equivalent in performance
2. Use `NUMERIC(p,s)` for money — floats have rounding errors
3. Use `TIMESTAMPTZ` over `TIMESTAMP` for real-world dates
4. Always use `BIGINT GENERATED ALWAYS AS IDENTITY` for new tables (not `SERIAL`)
5. NULL means unknown — `= NULL` never works, use `IS NULL`
6. `COALESCE(a, b, c)` returns the first non-NULL value
7. Foreign keys enforce referential integrity at the database level
